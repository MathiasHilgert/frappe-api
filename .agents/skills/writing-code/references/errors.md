# Errors

- Domain and use cases: expected business failures return `Result`; no exceptions (see `use-cases.md`).
- Infrastructure faults: a dedicated, package-private `RuntimeException` per failure kind (`EventPublicationException`, `NatsProvisioningException`, `MissingDatabaseSettingsException`), with an actionable message and the original exception as `cause` whenever there is one.
- Catch only what can actually be thrown and handled: name the types (`IOException | JetStreamApiException | JacksonException`). Never `catch (Exception)` or `catch (RuntimeException)`, except at the isolation boundaries below.
- Telemetry isolation boundary: recording telemetry (business metrics in `BusinessMetricsRecorder`) may catch `RuntimeException` per metric, because it runs user-declared lambdas and Micrometer registration inside the business call or its after-commit callback. It logs one WARN with `frappe.metric`, `frappe.event_type`, `frappe.event_id` and skips that metric; telemetry never fails or reaches the business caller.
- Localization isolation boundary: `LocaleChainResolver` may catch `RuntimeException` around each locale port (`UserLocalePreference`, `TenantLocaleDefaults`), because the ports run another module's arbitrary code on every request, health checks included. A failure counts as "no value" for that link (a failing tenant lookup means every supported language is enabled), is logged once per request at WARN with `frappe.locale_link` (`user_preference`, `tenant_defaults`) and the cause, and the chain continues; localization never fails a request. No other code uses these two boundaries.
- Log OR rethrow, never both. Log once, at the boundary that handles the failure and knows the context (a background task, a listener turning a failure into a failed future). Everything below it wraps and rethrows.
- `InterruptedException`: restore the flag (`Thread.currentThread().interrupt()`), then finish cleanup (close resources) before returning.
- No shared base exception while the exceptions are package-private; add one only when a caller outside the package needs to catch the family.
- Public exceptions are the exception to package-private: only when another module must catch them, declared in the platform root package next to the port that throws them (`SecretStoreUnavailableException` for `ShortLivedSecretStore` and `RateLimiter`).
- A boundary that turns a failure into a result (e.g. a failed `CompletableFuture`) is where it is logged. Frameworks may log the same failure again (Spring Modulith's INFO for failed listeners); that duplicate is known and accepted.
- Wrap third-party signals at the adapter boundary: jnats' `IllegalStateException` for a closed connection becomes `NatsUnavailableException` in `NatsClient`.
- Fail fast at startup for missing configuration, naming the environment variable to set.
- Stored events that no longer load (outbox rows of an older deployment): a missing class surfaces as `ClassNotFoundException` from `ClassUtils.forName`, and Modulith 2.1.1's `JacksonEventSerializer.deserialize` (an unwrapped `ObjectReader.readValue`) throws Jackson 3's `JacksonException` for JSON that no longer fits the class. Handle both per row (`PublicationRedelivery`) so one row never aborts a batch; catch those types, not `RuntimeException`.
- `HandlerMappingGuard` catches `Exception` around `HandlerMapping#getHandler`, which declares it: a mapping that cannot answer may serve the request, so the security decision fails closed (the request is refused). Nothing is logged; the caller gets 401/403.
- The other allowed `catch (RuntimeException)`: `PublicationRedelivery` around `TransactionalApplicationListener.processEvent`, because listener code is arbitrary and one failing listener must not abort the recovery batch (Modulith's own resubmission catches the same way). It marks the row failed and logs once. Any broad catch beyond those listed here is rejected in review; the scheduler entry point catches only `DataAccessException`.
